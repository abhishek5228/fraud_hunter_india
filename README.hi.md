# Fraud Hunter India (हिन्दी)

[English README](README.md)

**भारत के डिजिटल भुगतानों के लिए एक रियल-टाइम जोखिम इंजन।** हर UPI, IMPS, कार्ड और ATM भुगतान पर यह तीन में से एक जवाब देता है: **मंज़ूर (Approve)**, **दोबारा पुष्टि (Step-up)** या **रोकें (Decline)**। साथ में वजह भी बताता है, ताकि विश्लेषक या ग्राहक उस पर कार्रवाई कर सके।

सारा डेटा **सिम्युलेटेड** है। कोई असली ग्राहक या असली पैसा शामिल नहीं है।

## समस्या, एक कहानी में

आशा पटना में शिक्षिका हैं। रात 9 बजे SMS आता है: *"आपका बिजली कनेक्शन आज रात कट जाएगा। अभी इस नंबर पर कॉल करें।"* कॉल करने पर "अधिकारी" उनसे एक "सपोर्ट ऐप" डलवाता है। वह स्क्रीन-शेयरिंग ऐप है। आशा अपने ही फ़ोन को देखती रहती हैं, और ठग उनके UPI से **₹18,500 एक अनजान खाते में** भेज देता है। वह खाता एक **म्यूल अकाउंट** है, यानी किराये का खाता जो सिर्फ़ चोरी का पैसा आगे बढ़ाता है।

पुराना सिस्टम सिर्फ़ यह देखता: "क्या यह रकम आशा के लिए असामान्य है?" इसलिए भुगतान पास हो गया।

यह प्रोजेक्ट भुगतान के आसपास की हर चीज़ देखता है: स्क्रीन-शेयरिंग ऐप चालू है, पहली बार इस व्यक्ति को पैसे जा रहे हैं, प्राप्तकर्ता दुकान नहीं निजी खाता है, रकम सामान्य से 18 गुना है। नतीजा: **भुगतान रोका जाता है** और आशा को हिन्दी या अंग्रेज़ी में बताया जाता है कि क्या करें (1930 पर कॉल करें)।

इंजन का असली सवाल "क्या यह फ्रॉड है?" नहीं, बल्कि: **"फ्रॉड की कीमत और अच्छे ग्राहक को रोकने की कीमत देखकर सबसे सस्ता सुरक्षित क़दम कौन सा है?"**

## जल्दी शुरू करें

```bash
pip install -r requirements.txt
python -m fh.train                          # लगभग 35 सेकंड
python -m uvicorn fh.api:app --port 8000    # फिर http://localhost:8000 खोलें
python -m pytest -q tests                   # 150 टेस्ट
```

बिना सर्वर के डेमो: [`docs/index.html`](docs/index.html) खोलें।

## मुख्य बातें

| क्या | कैसे |
|---|---|
| **तीन जवाब** | Approve, Step-up, Decline, हर एक वजह के साथ |
| **सटीक कारण** | मॉडल जोड़-आधारित है, इसलिए हर कारण का असर सीधा गणित है |
| **सख़्त नियम** | नियम सिर्फ़ सख़्ती बढ़ा सकते हैं, कभी ढील नहीं दे सकते |
| **लागत के हिसाब से फ़ैसला** | ₹200 और ₹2 लाख के भुगतान को एक जैसा नहीं देखा जाता |
| **Scam Shield** | कोई भी SMS, UPI ID या QR पेस्ट करके भुगतान से पहले जाँच सकता है (हिन्दी और अंग्रेज़ी) |
| **Mule graph** | एक ही खाते को पहली बार पैसे भेजने वाले कई अनजान लोग, ग्राफ़ में |
| **Backtest** | अपनी पुरानी CSV चलाकर देखें कि इंजन क्या करता |
| **Red team** | इंजन खुद पर हमला करके अपनी कमज़ोरियाँ ढूँढता है |
| **Razorpay (टेस्ट मोड)** | साइन किया हुआ webhook असली भुगतान घटनाओं को इंजन तक लाता है |
| **निष्पक्षता की जाँच** | कौन से ग्रुप के ईमानदार ग्राहक सबसे ज़्यादा रोके जाते हैं |

सभी 54 फ़ीचर, उदाहरणों और आरेखों के साथ, [अंग्रेज़ी README](README.md) में हैं।

## ईमानदारी से सीमाएँ

- **सारा डेटा सिम्युलेटेड है।** असली प्रदर्शन के लिए किसी बैंक का लेबल किया हुआ इतिहास चाहिए।
- यह **असली पैसे के लिए तैयार नहीं** है।
- सादा logistic regression यहाँ जोड़-आधारित मॉडल जितना ही सटीक है; GAM इसलिए रखा गया कि उसे समझा जा सकता है।
- OTP वाला step-up कई ठगियों को नहीं रोकता (ठग को OTP मिल जाता है, या पीड़ित खुद मंज़ूर कर देता है)।
